## 1. 概述
### 1.1 模块背景与目标
智能评估模块是AI应用开发和优化流程中的关键组件，旨在为大语言模型(LLM)应用（尤其是RAG应用）提供全面的测试、评估和优化能力。模块通过标准化的测试数据集管理、多维度的评估指标体系和自动化的优化闭环，帮助开发者提升AI应用的质量和性能，降低模型幻觉、提高检索稳定性，并优化整体交互体验。

### 1.2 模块功能范围
本模块主要包含三大核心功能域：

+ 测试数据集管理：实现测试数据的生成、管理和质量评估
+ 评估任务管理：提供LLM应用评估的全流程支持
+ AI应用优化器：基于评估结果生成优化方案并执行优化

### 1.3 术语定义
+ **RAG (Retrieval-Augmented Generation)**：检索增强生成，一种结合外部知识检索的LLM应用架构
+ **模型幻觉 (Hallucination)**：LLM生成不符合事实或上下文的内容
+ **评估指标**：用于衡量AI应用性能的量化标准
+ **优化闭环**：评估-建议-执行-再评估的循环优化过程

## 3. 模块详细设计
### 3.1 测试数据集管理模块
#### 3.1.1 测试数据集管理
##### 3.1.1.1 数据集CRUD功能
+ **创建数据集**
    - 支持手动创建：用户输入数据集基本信息(名称、描述、应用关联等)
    - 支持Excel导入：通过上传包含`请求`、`期望输出`、`上下文`三列的Excel文件创建
    - 自动生成：用户指定RAG应用后，系统基于应用配置自动生成测试数据集
+ **读取数据集**
    - 支持按ID、名称、应用关联等条件查询
    - 支持分页、排序查询
    - 支持数据集详情查看，包括版本历史
+ **更新数据集**
    - 支持数据集基本信息更新
    - 支持数据集内容更新(追加或修改测试用例)
    - 版本控制：每次更新生成新数据集版本，可查看版本差异
+ **删除数据集**
    - 支持单个或批量删除
    - 软删除机制：可恢复已删除数据集
    - 级联删除控制：关联的评估任务需先处理

##### 3.1.1.2 数据集质量评估
+ **评估指标**：
    - 请求可回答性：分析请求是否可基于提供的上下文回答

    - 期望输出准确性：验证期望输出是否与上下文一致
    - 数据格式规范性：检查数据格式是否符合要求，如简洁、问答风格一致
    - 自定义指标/人工审核
+ **评估流程**
    1. 用户触发质量评估
    2. 系统对数据集中的每个测试用例进行分析
    3. 生成质量评估报告，包含各项指标得分和改进建议
    4. 报告可下载或在界面查看

### 3.2 评估任务管理模块
#### 3.2.1 RAG评估算法
+ **内置评估指标**：
    - _检索质量评估‌：_
        * 上下文精准度（Context Precision）
            + 定义：衡量检索结果中有效信息占比。
            + 计算方法：基于question与contexts的匹配度分析。‌‌‌‌
        * 上下文召回率（Context Recall）‌
            + 定义：评估是否捕获解答问题所需的全部相关信息。
            + 计算方法：对比contexts与ground_truth的重合度。‌‌‌‌
    - ‌_生成质量评估‌：_
        * 忠实度（Faithfulness）‌
            + 定义：检测生成答案与检索上下文的事实一致性。
            + 计算方法：分析answer在contexts中的支持证据比例（0-1评分）。‌
        * ‌答案相关度（Answer Relevancy）‌
            + 定义：评估答案与问题的逻辑关联性。
            + 计算方法：通过LLM判断答案是否直接解决核心问题。
    - _其他扩充指标：_
        * <font style="color:rgb(51, 51, 51);">答案正确性：答案与标准答案的匹配度</font>
+ **<font style="color:rgb(51, 51, 51);">算法方案选型</font>**
    - 基于规则的评估：预设规则匹配
    - <font style="color:rgb(51, 51, 51);">基于LLM的评估：使用辅助LLM进行评估</font>
    - <font style="color:#DF2A3F;">混合评估：结合规则和LLM评估优势</font>
+ **实现路径**

### 3.3 AI应用优化器模块
#### 3.3.1 优化指引生成
+ **优化维度**：
    - 提示词优化：生成更有效的提示词模板
    - 检索优化：改进检索策略和参数
    - 上下文处理：优化上下文选择和处理逻辑
    - 模型选择：推荐更适合的LLM模型
    - 数据优化：建议测试数据集改进方向
+ **指引生成流程**
    1. 分析评估结果，识别性能瓶颈
    2. 基于瓶颈生成针对性优化建议
    3. 对建议进行优先级排序
    4. 生成结构化优化指引报告

#### 3.3.2 自动优化执行
+ **优化闭环流程**
    1. 评估：对当前应用状态进行评估
    2. 分析：识别问题和优化机会
    3. 建议：生成优化方案
    4. 执行：自动实施优化措施
    5. 再评估：验证优化效果
    6. 循环：根据再评估结果决定是否继续优化
+ **支持的优化操作**
    - 提示词自动调整
    - 检索参数优化
    - 模型配置调整
    - 知识库更新
    - 数据增强

## 6. 算法设计
### 6.1 数据集质量评估算法
#### 6.1.1 请求可回答性评估
+ **算法逻辑**：
    1. 分析请求文本，提取关键信息
    2. 在上下文中查找是否包含回答请求所需的信息
    3. 评估上下文信息的充分性
    4. 生成可回答性得分(0-100)
+ **评分标准**：
    - 上下文包含完整答案：90-100分
    - 上下文包含部分答案：60-89分
    - 上下文不包含答案但相关：30-59分
    - 上下文不相关：0-29分

#### 6.1.2 期望输出准确性评估
+ **算法逻辑**：
    1. 将期望输出与上下文进行语义匹配
    2. 检查期望输出是否包含上下文中没有的信息
    3. 评估期望输出的完整性和准确性
    4. 生成准确性得分(0-100)
+ **评分标准**：
    - 完全符合上下文：90-100分
    - 大部分符合上下文：60-89分
    - 部分符合上下文：30-59分
    - 不符合上下文：0-29分

### 6.2 RAG评估算法
#### 6.2.1 模型幻觉检测算法
+ **算法逻辑**：
    1. 运行RAG应用处理测试用例
    2. 提取LLM生成的回答
    3. 将回答与上下文进行对比，识别不一致内容
    4. 分析回答中是否包含上下文以外的"幻觉"内容
    5. 计算幻觉程度得分(0-100)
+ **检测方法**：
    - 基于规则的检测：预设幻觉模式匹配
    - 基于LLM的检测：使用辅助LLM判断回答真实性
    - 对比检测：比较相同输入的不同输出

#### 6.2.2 检索稳定性评估算法
+ **算法逻辑**：
    1. 对同一查询多次运行RAG应用
    2. 收集每次运行的检索结果
    3. 计算检索结果之间的相似度
    4. 生成稳定性得分(0-100)
+ **相似度计算方法**：
    - 向量空间模型相似度
    - Jaccard相似度
    - 语义相似度(基于LLM)

### 6.3 优化建议生成算法
#### 6.3.1 优化优先级算法
+ **算法逻辑**：
    1. 分析评估结果，识别所有潜在优化点
    2. 对每个优化点计算影响因子(基于评估指标变化)
    3. 计算优化实施难度
    4. 综合影响因子和难度计算优先级得分
    5. 按优先级排序优化建议
+ **优先级计算公式**：  
`优先级 = 影响因子 × (1 / 难度系数)`

#### 6.3.2 自动优化执行算法
+ **算法逻辑**：
    1. 根据优化建议生成执行计划
    2. 按优先级顺序执行优化措施
    3. 每步优化后进行小范围评估
    4. 根据中间评估结果调整后续优化策略
    5. 完成所有优化后进行全面评估
    6. 生成优化效果报告

#### 8.3.1 集成架构优化描述
##### 1. 微服务集成定位
将智能评估模块作为 FastGPT 平台内的独立微服务部署，与现有 `sandbox` 和 `mcp server` 服务同级，形成完整的 AI 应用开发生命周期闭环：

+ **数据层面**：对接 FastGPT 的知识库、应用配置及对话数据
+ **接口层面**：通过 FastGPT 开放 API 实现双向交互
+ **部署层面**：采用容器化部署，与 FastGPT 核心服务共享注册中心和配置中心



##### 2. 集成技术方案
###### （1）认证机制集成
+ **APIKey 认证**：遵循 FastGPT 认证规范（参考 [https://doc.tryfastgpt.ai/docs/development/openapi/intro/）](https://doc.tryfastgpt.ai/docs/development/openapi/intro/）)
+ **权限控制**：
    - 评估模块需申请 `app:read`、`app:write`、`dataset:read` 等权限范围
    - 支持通过 JWT 令牌传递用户身份信息至 FastGPT 接口

###### （2）核心接口集成清单
| **功能模块** | **接口类型** | **接口用途** | **集成方式** |
| --- | --- | --- | --- |
| **应用管理** | `POST /api/core/app/list` | 获取应用列表，用于评估任务关联目标应用 | 周期性同步应用元数据 |
|  | `GET /api/core/app/detail` | 获取应用配置（版本、知识库、模型参数），作为评估依据 | 评估任务启动时实时调用 |
| **对话交互** | `POST /api/v2/chat/completions` | 调用 FastGPT 应用进行对话测试，获取实际输出用于评估对比 | 评估任务执行阶段批量调用 |
| **应用优化** | `POST /api/core/app/version/publish` | 基于评估结果更新应用配置（如优化提示词、调整检索参数） | 优化闭环执行阶段主动调用 |
| **知识库管理** | `GET /api/core/dataset/list` | 获取知识库列表，用于数据集生成和评估场景匹配 | 数据集管理模块依赖 |
|  | `GET /api/core/dataset/detail` | 获取知识库详情（文档数量、分片配置），辅助评估数据集质量 | 质量评估阶段调用 |
| **文档分片** | `POST /api/core/dataset/collection/listV2` | 获取文档列表，用于生成上下文相关测试用例 | 数据集自动生成模块核心依赖 |
|  | `POST /api/core/dataset/data/v2/list` | 获取分片内容，用于评估检索准确性和上下文利用率 | 检索稳定性评估阶段调用 |


###### （3）数据交互流程
1. **评估数据导入**：
    1. 将 FastGPT 应用的历史对话数据同步至评估模块，作为测试数据集基础
    2. 将 FastGPT 应用关联的知识库相关分片以主题聚合并同步至评估模块，用于生成测试数据集
2. **评估任务执行**：
    1. 评估任务执行前需要从FastGPT获取大模型/embedding配置，用于初始化对应的模型客户端
    2. 评估任务执行中，会基于每个测试用例构造app chat请求并调用，用于评估AI应用的表现
3. **评估结果导出**：评估报告同步至 FastGPT 控制台，支持在应用详情页查看
4. **优化指令执行**：评估模块生成的优化方案通过 API 推送给 FastGPT 应用引擎执行
